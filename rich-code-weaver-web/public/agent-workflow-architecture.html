03 / DELTA
ARCHITECTURE DELTA

改造带来什么

变化集中在四个位置：完成判定、修复方式、工具边界和运行可观测性。

维度 原有实现 当前实现 直接结果
完成判定 最后节点结束；Agent 以模型最终回复为准 deliveryReady 统一门禁；Agent 流完成自动执行 exit 失败产物不能进入完成态
审查职责 结构检查、AI 审查、异常处理混在同一节点 确定性预检、AI 语义审查、真实构建拆成独立节点 错误定位更直接
异常语义 AI 审查异常按通过继续 异常按未通过处理，进入修复或失败终态 质量链路失败关闭
修复循环 最多 2 轮，以提示词增强重新生成 最多 3 轮；预检、审查、构建证据进入修复上下文 修复更接近真实错误
Vue 构建 构建失败被吞掉，仍可能结束 npm 安装、npm run build、dist 校验成为交付前置条件 部署前暴露构建错误
Agent 边界 工具各自拼接路径，退出无验证 统一项目路径解析器；validate、build、exit 形成硬约束 越界与提前退出被拦截
运行状态 “看起来完成”与“构建完成”边界模糊 结构化阶段输出、工具结果摘要、明确失败终态 前端展示与后端事实一致
