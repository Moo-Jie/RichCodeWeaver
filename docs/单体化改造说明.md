# 单体重构说明

## 1. 改造结果

原 9 个业务 Maven 模块合并为 `rich-code-weaver-monolith`，保留原包边界。唯一启动类为 `com.rich.RichCodeWeaverApplication`，唯一 HTTP 端口为 8101，上下文路径继续为 `/api`。

| 原模块 | 单体中的包 |
| --- | --- |
| rich-code-weaver-common | `com.rich.common` |
| rich-code-weaver-model | `com.rich.model` |
| rich-code-weaver-user | `com.rich.user` |
| rich-code-weaver-generator | `com.rich.app` |
| rich-code-weaver-ai | `com.rich.ai`、`dev.langchain4j` 定制类 |
| rich-code-weaver-file | `com.rich.file` |
| rich-code-weaver-prompt | `com.rich.prompt` |
| rich-code-weaver-social | `com.rich.social` |
| rich-code-weaver-client | `com.rich.user.api`、`com.rich.file.api`、`com.rich.prompt.api` |

原 5 个内部契约全部改为本地 Spring Bean：

- `InnerUserService` → `com.rich.user.api.InnerUserService`
- `InnerCollaboratorService` → `com.rich.user.api.InnerCollaboratorService`
- `InnerFileService` → `com.rich.file.api.InnerFileService`
- `InnerScreenshotService` → `com.rich.file.api.InnerScreenshotService`
- `InnerSystemPromptService` → `com.rich.prompt.api.InnerSystemPromptService`

## 2. 调用改造

- 5 个服务实现由 `@DubboService` 改为 `@Service`。
- 20 个 `@DubboReference` 改为 `@Resource`，接口、方法签名、参数和返回结构不变。
- `user` 对 `file.FileService`、`generator` 对 `com.rich.ai` 的调用保持本地 Bean 调用。
- 两个 `@AuthCheck` 切面只保留 user 包中的全局切面，避免同一请求重复鉴权。
- 合并后的 Bean 名称冲突已显式处理：
  - `generatorHealthController`、`fileHealthController`、`promptHealthController`、`socialHealthController`、`userHealthController`
  - `generatorRabbitMQConfig`、`fileRabbitMQConfig`
  - `generatorWebSocketConfig`、`userWebSocketConfig`
- RabbitMQ 队列、交换机、路由键与死信配置保留；文件上传消费者使用独立的 `fileRabbitListenerContainerFactory`，保留原最大并发数 5。

## 3. 移除内容

- 根 POM 中的 Dubbo BOM、`dubbo.version`。
- 各模块的 `dubbo-spring-boot-starter`、`dubbo-nacos-spring-boot-starter`。
- `@EnableDubbo`、`@DubboService`、`@DubboReference` 及全部 Dubbo import。
- 所有 `dubbo:` 配置项。
- 5 个独立业务启动类及 9 个模块 POM。
- `rich-code-weaver-client` 远程契约模块。
- 服务模块的 `application-local-tmp.yml`、`application-prod-tmp.yml`、`mcp-servers-tmp.json`、`prometheus-tmp.yml`。
- `ImageSearchTool` 中带默认值的第三方 API Key。

## 4. 保留内容

- Nacos Config 与可选 Nacos Discovery。
- Higress 外部入口；原 Controller 路径与 `/api` 前缀不变。
- Prometheus、Micrometer、Actuator；抓取路径仍为 `/api/actuator/prometheus`。
- Redis、Spring Session、Redisson、RabbitMQ、OSS、邮件、MCP、RAG。
- MyBatis-Flex Snowflake ID 与本地 Spring 事务。

## 6. 路径与网关

- 单体继续监听 `8101`，`server.servlet.context-path=/api`。
- `/api/user/**`、`/api/generator/**`、`/api/file/**`、`/api/social/**`、`/api/prompt/**`、`/api/actuator/prometheus`、`/api/user/ws/chat`、`/api/generator/ws/task` 均保持不变。
- Higress/Nginx 需要把原先指向 8102 至 8105 的上游统一改为 8101；路径、前缀和鉴权规则不需要改。
- 仓库没有 Higress 路由 CRD，实际路由与插件配置需从 Higress 控制台导出核对。

## 7. 验证与风险

已完成：

- `mvnw -DskipTests compile`：405 个主源码文件编译通过。
- `mvnw -DskipTests test-compile`：3 个测试源码文件编译通过。
- `rich-code-weaver-server-admin` 独立打包通过。
- `npm run build`：Vue 类型检查与 Vite 生产构建通过。
- 全仓扫描无 Dubbo/RPC 注解、依赖与配置。
- 代码中无默认 API Key、数据库连接串、Redis 地址等业务连接值。
- Bean 名称冲突已显式命名，`spring.main.allow-bean-definition-overriding` 保持 `false`。

需要启动后验证：

- Nacos Config 拉取、刷新与可选服务发现。
- MySQL、Redis、RabbitMQ、OSS、SMTP、PGVector/Milvus/Elasticsearch 连接。
- 两套 WebSocket 端点、SSE 续传和 `@AuthCheck` 鉴权。
- RabbitMQ 消费者并发、死信重试与多副本本地文件路径。
- Higress 将各路径统一转发到 8101 后的实际行为。
- Prometheus 抓取与 AI、任务指标上报。
